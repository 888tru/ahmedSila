# CLAUDE.md

Контекст проекта для будущих сессий. Архитектурные обоснования — в `TECH_STACK.md`,
здесь: что уже написано, почему именно так, и на какие грабли не наступать.

## Что это

Внутренняя панель управления тенантами (магазинами и супермаркетами) — инструмент
нашей команды: список клиентов, их метрики, тикеты поддержки, управление доступом
внутри команды. Целевой сервис (софт для операторов и кассиров) пишется **отдельно
и позже**; контракт между ними — gRPC, проектируется, когда дойдёт до интеграции.

Суперадминка **не** multi-tenant: это одна панель, видящая всех клиентов.

## Команды

```
task up            # Postgres + Redis (нужен запущенный Docker Desktop)
task migrate-up    # goose
task migrate-down  # откат — проверять сразу, а не перед релизом
task sqlc          # перегенерировать код доступа к БД после правки SQL
task gen-keys      # Ed25519-ключи для .env
task run           # сервер на :8080
task test          # go test ./... -race
task lint          # golangci-lint
```

Тулинг ставится в `$env:USERPROFILE\go\bin` — он **не** в PATH текущей сессии
PowerShell по умолчанию. В командах приходится делать:

```powershell
$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' +
            [Environment]::GetEnvironmentVariable('Path','User') + ';' + "$env:USERPROFILE\go\bin"
```

## Архитектура

Clean Architecture, правило зависимостей: `delivery → usecase → domain ← repository`.

```
cmd/server            сборка графа зависимостей (единственное место, где выбираются реализации)
cmd/genkeys           генерация Ed25519-ключей
internal/domain       сущности + порты (интерфейсы). Не импортирует Gin, sqlc, Redis
internal/usecase      бизнес-логика поверх портов
internal/repository/postgres   репозитории поверх sqlc; queries/ — исходный SQL
internal/repository/sqlc       сгенерированный код, руками не править
internal/delivery/http         Gin: router, middleware, handler, response
internal/pkg          jwt, authz, authprovider, hash, config, redisx
migrations            goose SQL
web                   React + TS (Vite), Tailwind v4, TanStack Query/Table, react-router
web/src/components    оболочка (layout) и примитивы UI, общие для всех экранов
web/src/features      экраны по предметным областям; сейчас только clients
web/src/features/clients/tabs   вкладки карточки клиента
web/src/lib           форматирование дат/чисел, склейка классов
```

## Ключевые решения и зачем

| Решение | Зачем именно так |
|---|---|
| Порты в `domain`, реализации в `pkg` | MVP-реализация всегда одна и простая. SSO — это второй `AuthProvider`, Casbin — второй `Authorizer`; `usecase` при этом не меняется |
| **Casbin отложен**, вместо него таблица прав | Для четырёх фиксированных ролей Casbin — это model-файл, адаптер и синхронизация политик между инстансами. Граница (`domain.Authorizer`) даёт ту же расширяемость без этой цены |
| **Ed25519 (EdDSA)**, а не HS256 | Позже целевой сервис должен проверять подпись по публичному ключу через JWKS, не имея приватного. С симметричным ключом это означало бы смену схемы подписи на ходу. `kid` в заголовке заложен под ротацию ключей |
| Refresh — непрозрачная строка, не JWT | Он проверяется только по хешу в БД. В БД лежит SHA-256, а не сам токен: дамп таблицы не даёт войти |
| `session_id` + ротация с детектом переиспользования | Предъявили уже использованный refresh → это утечка. Отзывается **вся цепочка**, а не один токен. Без `session_id` отозвать «всю сессию» было бы нечего |
| Аудит — отдельный порт, ошибка записи игнорируется в usecase | Журнал не должен ронять основную операцию. Единственное место, где ошибка записи видна, — `AuditRepo`, поэтому у него есть логгер |
| `Clock` как зависимость | Тесты на протухание токенов и lockout не должны зависеть от реальных часов. `jwt.Issuer` тоже принимает `Clock` — см. грабли ниже |
| Единый маппинг ошибок в `delivery/http/response` | Хендлеры возвращают доменную ошибку и не выбирают статус. Иначе один и тот же `ErrNotFound` со временем станет то 404, то 400 |
| Конфиг падает на старте без обязательных переменных | Приложение не должно подниматься «условно рабочим» с localhost-подключением в проде. `CORS_ALLOWED_ORIGINS=*` запрещён явно |
| Redis недоступен → **fail-closed** (503) | Это внутренняя панель команды: цена ложного отказа несопоставима с ценой пропуска отозванного токена. Для контура тенантов решение принимать отдельно — там отказ означает вставший магазин |
| `ErrInvalidCredentials` одинаков для «нет учётки», «неверный пароль» и «учётка приостановлена» | Иначе login становится оракулом существования учёток. Для несуществующего пользователя вызывается `DummyVerify()` — чтобы совпадало и время ответа |
| Блокировка проверяется **после** пароля | Иначе ответ «заблокировано» получает любой, кто просто угадал существующий email |
| Деньги — `bigint` в минорных единицах + колонка валюты | Никакого float. Суточная агрегация — в таймзоне тенанта, иначе цифры не сойдутся с тем, что видит магазин |

## Конвенции

- **Ошибки**: доменные — в `domain/errors.go`; репозитории переводят ошибки драйвера
  в доменные через `mapError` (`repository/postgres/postgres.go`). В `usecase`
  проверять только через `errors.Is`.
- **Аудит**: действия — константы в `domain/audit.go`, не строковые литералы по коду.
- **Права**: только через `domain.Authorizer` / `middleware.Require`, никогда
  `if user.Role == "admin"`.
- **Статусы и планы**: Postgres enum, не строки. Новое значение — миграция.
- **Комментарии**: объясняют «почему», а не «что». Очевидное не комментируем.
- **Язык**: комментарии и сообщения ошибок — русские, идентификаторы — английские.

## Грабли

1. **`jwt.Parse` и время.** Валидация `exp` идёт по `Clock` из `jwt.Config`, а не по
   системным часам. Это уже ловило баг: в тестах с управляемым временем токен
   рождался просроченным. В тестах передавайте тот же `Clock`, что и в usecase.
2. **sqlc читает `migrations/` напрямую.** Меняете схему — обязательно `task sqlc`,
   иначе сгенерированный код разойдётся с БД.
3. **goose требует `-- +goose StatementBegin/End`** вокруг каждого выражения
   с телом (функции, триггеры) — иначе миграция разъедется по точкам с запятой.
4. **`go install` в одном скрипте молчит об ошибках.** Exit code — от последней
   команды. Проверять `if ($?)` после каждой установки (уже обжигались: goose
   и golangci-lint «установились» с кодом 0, но бинарников не появилось).
5. **`go mod tidy` выкидывает зависимости**, которые ещё никто не импортирует.
   Не пугайтесь `no required module provides package` сразу после tidy — просто
   добавьте импорт и повторите.
6. **Docker Desktop** должен быть запущен до `task up`; CLI есть всегда, движок — нет.
7. **TanStack Table здесь v9, а не v8.** Почти все примеры в сети — v8 и не
   компилируются: вместо `useReactTable` + `getCoreRowModel()` в опциях —
   `useTable({ features })`, где фичи подключаются явно через `tableFeatures`
   (`web/src/features/clients/table.ts`). Меta колонки типизируется слотом
   `columnMeta` в `tableFeatures`, а не глобальным `declare module`. Актуальный
   API — в `node_modules/@tanstack/react-table/skills/`, там же гайд по миграции.
8. **`node`/`npm` не в PATH сессии PowerShell** — как и Go-тулинг, добавляются
   тем же префиксом с machine/user PATH.
9. **Мок обязан возвращать копии объектов.** React Query сравнивает старые
   данные с новыми и, получив ту же ссылку, считает, что ничего не изменилось.
   Мок-стор мутирует записи на месте, поэтому читающие методы отдают `{...}` —
   иначе мутация проходит, а экран не перерисовывается (уже ловили на
   приостановке доступа).
10. **Колбэки в `mutate(args, { onSuccess })` не вызываются**, если компонент
    успел размонтироваться. Для удаления клиента это ровно тот случай —
    `onSuccess` объявлен на самом хуке (`useDeleteClient`), а не в вызове.
11. **BrowserRouter требует SPA-fallback на раздаче.** В dev его даёт Vite,
    но прод-сборку нужно отдавать с перенаправлением неизвестных путей на
    `index.html`, иначе прямая ссылка на `/clients/5/access` даст 404.

## Состояние

**Готово:** тулчейн, скелет репозитория, миграция `0001` (`super_admin_users`,
`refresh_tokens`, `audit_logs`), domain с портами, auth-usecase (login/refresh/
logout/logout-all), репозитории на sqlc, HTTP-слой, `cmd/server`, `cmd/genkeys`.

**Готово во фронтенде:** оболочка (сайдбар + topbar), роутер и пять экранов из
восьми в `PAGES.md` — «Обзор» (§1: показатели с дельтой, триалы, заканчивающиеся
скоро, лента последних событий), «Клиенты — список» (§2), «Клиент — карточка»
(§3, все четыре вкладки, приостановка с причиной, код подтверждения, удаление
через подтверждение названием), «Создание клиента» (§4: форма с проверками на
месте, занятость email отдельным запросом, тариф и статус при создании, модалка
с кодом подтверждения) и «Обращения» (§5: переписка по всем клиентам сразу —
фильтры по статусу и сотруднику, открытие треда, смена приоритета). Сделаны
раньше очереди из §5 TECH_STACK (фронт после бэкенда), поэтому данные берутся
из мока: ручек по клиентам и обращениям ещё нет. Границы — `features/*/api.ts`
(сигнатуры уже как у будущего API) и `features/*/mock.ts` (данные, у клиентов —
ещё и мутации в памяти); всё удаляется целиком вместе с `VITE_USE_MOCK=false`.
На «Обращениях» назначение на себя, отметка «решено» и отправка ответа — тоже
пока без бэкенда, кнопки заведены, но ничего не пишут (см. `POST
/api/v1/tickets/:id`, `/messages` в «Дальше»); смена приоритета — реальная, но
только в состоянии экрана.

**Проверено:** `go build`, `go vet`, `golangci-lint run` (0 issues), 13 тестов
auth-usecase (ротация, reuse detection, lockout, изоляция сессий,
неразличимость ошибок входа); во фронтенде — `npm run build` (tsc + vite) и
`npm run lint`, экраны прогнаны в браузере: фильтры, поиск, плотность,
пагинация, пустые состояния, все четыре вкладки карточки, приостановка с
проверкой причины, генерация кода, удаление с подтверждением и возврат в
список, обновление счётчиков в списке после мутации; на создании клиента —
вёрстка формы, проверка обязательных полей, ошибка «email уже используется» по
ходу заполнения и создание клиента с переходом в его карточку; на «Обращениях»
— фильтры по статусу и сотруднику вместе (включая пустое состояние со сбросом),
открытие и закрытие треда, смена приоритета (отражается и в списке, и в
шапке треда), переход по имени клиента в его карточку без открытия треда.

**Не проверено:** миграции на живой БД — не был запущен Docker Desktop.
Первым делом в следующей сессии: `task up && task migrate-up && task migrate-down`.
Во фронтенде глазами не проверены кнопки в модалке с кодом («Скопировать»,
«Отправить в WhatsApp», «Создать ещё одного») — расширение браузера перестало
доставлять клики на страницу посреди прогона.

**Дальше:** `cmd/seed` (первый owner), интеграционные тесты репозиториев на
testcontainers, тесты хендлеров, затем тенанты с `desired_status`/`observed_status`
и аудит-декоратором — и вместе с ними ручки по клиентам и обращениям, чтобы
снять мок: `GET /clients`, `POST /clients`, `GET /clients/:id`,
`/clients/:id/tickets`, `/clients/:id/journal`, `GET /clients/email-taken`,
`POST /suspend`, `/resume`, `/activation-code`, `DELETE /clients/:id` (список —
в `features/clients/api.ts`), а также общая `GET /tickets` и мутации
`POST /tickets/:id` (назначение, статус), `POST /tickets/:id/messages` (ответ)
для «Обращений» (`features/tickets/api.ts`). `POST /clients` обязан отдавать
карточку сразу с первым кодом подтверждения — модалка после создания берёт код
из ответа, отдельного запроса за ним нет.
Во фронтенде дальше — раздел команды; пункт сайдбара под него уже нарисован и
ждёт маршрута.

**Не делаем в MVP:** gRPC и `.proto`, Kubernetes, Casbin, SSO, биллинг,
status page, read replicas, RLS (она нужна в целевом сервисе).
